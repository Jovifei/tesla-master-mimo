# 新行程到达 App 修复计划

目标：真实已结束行程自动进入当前账号、服务器和车辆作用域；自托管模式不需先刷新仪表盘，云模式通过长期归档或 Fleet Telemetry 持续读取。

## 执行阶段

1. P0 对同一行程核对 TeslaMate PostgreSQL、Adapter、云端历史和手机缓存，找到首个断点。
2. P1 以测试驱动修复 Android 主动刷新、车辆作用域和晚到响应隔离，保留离线缓存。
3. P2-A 加固并启用 Jovi 个人 TeslaMate 只读归档；身份必须以稳定 provider vehicle id 核验，不能按昵称或数字 carId 猜测。
4. P2-B 为 Fleet 配置补充脱敏阶段、上游状态和关联 ID，定位配置、TLS、接收、MQTT 或落库断点。
5. P3 完成双账号隔离、真机、三趟行程、一次充电和七天并行观察；真实 Fleet 首事件以前不得宣称项目完成。

## 安全和回退

- 不请求或输出 Tesla 密码、MFA、令牌、VIN、位置和原始上游正文。
- 不卸载或清除 `com.matelink`；只允许同签名 `adb install -r`。
- bridge 仅使用 SELECT 角色，凭据限制到一个账号、车辆和来源，撤销绑定或停止容器即可回退。
- 生产迁移为加性迁移；部署保留上一镜像和源目录，失败时仅回滚 API/bridge，不删除历史证据。
