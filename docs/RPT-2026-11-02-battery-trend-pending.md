# 电池趋势归档等待：问题与候选修复记录

- 发现日期：2026-11-02（Asia/Shanghai）。
- 审查基线：服务端提交 `8d3da22eeffbe251b031b561d34da2323c16cf69`；本文修复目前是本地未提交候选，没有部署，也没有新的发布版本号。
- 范围：TeslaMate 原归档桥、云端行程归档和独立电池趋势桥之间的先后顺序；不修改 App 页面、原桥游标、行程、充电记录或用户费用。

## 问题与证据

独立趋势桥和原归档桥分别轮询同一来源。新行程结束后，趋势桥可能先把电池样本发到云端，此时同一来源的行程尚未被原桥归档。基线服务端把这个场景与来源、时窗或历史证据真正冲突统一返回 `409`；现有趋势桥把 `409` 视为永久错误，停止并保留待发送批次。

这是代码和隔离测试中确认的竞态条件；不能仅凭本记录认定它已经导致某一真实行程丢失。原桥的已确认最大行程编号不是逐条存在证明：它可能越过未完成的较小编号，服务端对被隔离的记录也可能返回无操作收据。候选修复不依赖该游标判断云端是否已有行程。

## 本次候选

- 服务端先在事务内验证绑定、车主及完整来源作用域，并逐条预检整批样本。只有新批次没有旧回执、缺失的样本自身没有已有趋势证据，且其目标归档行的规范 ID 和同作用域来源自然键都不存在时，才返回固定的 `503 battery_trend_archive_pending` 和 `Retry-After: 60`。同批其他样本已有且一致的证据不会阻止等待。此响应不包含账号、车辆、来源编号、时间或位置。
- 已存在但来源、身份、起止时间或隔离状态不符，已有证据与内容不一致，以及已确认批次重放时来源行消失，仍返回 `409`。请求体哈希不符仍为 `422`；无效、撤销或到期的绑定仍走既有认证错误。
- 整批预检中真实冲突优先于缺失。等待或冲突时不插入趋势证据、不生成批次回执、不消耗趋势证据序列，也不修改既有数据。趋势事务按车辆归属、绑定、行程/证据的顺序加锁并复验绑定；锁等待取消等数据库错误只返回通用不可用，不冒充“等待归档”。
- 缺失归档的冲突探测拆分为主键、归档来源自然键、非归档来源自然键和 `NULL` 来源兜底，避免将归档部分索引排除在查询之外。在 PostgreSQL 16、3 万条合成行程的隔离 `EXPLAIN ANALYZE` 中，未关闭顺序扫描或强制优化器参数，实际选中了主键、归档和非归档索引；计划选择可能随版本和统计量变化，测试只记录计划而不将具体索引作为功能门槛。非归档分支仍可能随单车同类历史量增加而扫描更多记录，旧库若允许 `NULL` 来源也可能产生额外扫描，不能视为固定开销。
- 独立桥生产代码未改。它原本会按轮询间隔和 `Retry-After` 重试 `503`；待发送字节、批次编号及原游标保留，只有得到匹配的成功回执才推进独立游标。

专项覆盖：先缺后到并幂等重放；部分批次无写入和无序列消耗；两种顺序的冲突优先；自然键/规范 ID、跨账号、已存证据和已确认回执冲突；车主并发变化、锁等待取消和绑定等待期间到期；非隔离状态的既有资格；现有桥收到 `503` 后遵守等待时间、保留冻结批次并在服务恢复或进程重启后重放。

## 上线前提与未解决事项

1. 新错误码会向持有**有效同作用域绑定凭据**的一方透露“该来源记录当前是否存在”这一位信息。固定响应和鉴权降低暴露，但 `Retry-After` 不是强制限流。部署前必须核实并配置实际生效、可跨实例约束的适当限频；仓库中的 nginx 模板不能证明线上已生效。
2. `503` 只表示当前没找到归档行，不保证它一定会出现。现有桥会低频持续重试同一冻结批次，因此后续批次可能被阻塞；尚需可观测告警和安全的人工处理流程。
3. 本补丁不会自行重启此前已停止的趋势进程，也不提供电脑或 Docker 重启后的自动重新注入凭据；当前独立趋势容器的重启策略为 `no`。也不提供已处理旧编号的周期回扫或对已存证据的自动覆盖。归档授权到期或撤销后仍需安全续绑。
4. 候选按车辆归属、绑定、行程/证据的顺序加锁，以对齐普通归档修复；数据库错误仍须作为通用失败并回滚。本次已测锁等待取消、并发归属变更及等待车辆锁时撤销绑定，没有声称已实测所有死锁调度。普通归档候选已完成上文所述本地组合回归；仍不能视为最终提交 CI 或生产验收。
5. 正式发布前需在最终冻结提交上重跑组合测试、独立审查和实际部署预检；发布顺序应先部署兼容的服务端，再验证现有桥对真实 `503` 的等待与后续恢复。本文不代表已获线上发布验收。
