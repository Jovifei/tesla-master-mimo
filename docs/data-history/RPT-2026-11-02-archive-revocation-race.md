## 根因与候选修复

| 环节 | 原实现 | 候选边界 |
| --- | --- | --- |
| 初始认证 | `archive_binding.go` 的 `archiveBindingResource` 在解析请求体前查询绑定；通过后只把绑定快照交给后续导入。 | 初始认证、来源和请求体验证仍在锁外完成；只传递绑定快照与凭据摘要，不记录或持久化明文凭据。 |
| 撤权与写入 | `historyArchiveImportForBinding` 调用 `telemetry_import.go` 的 `importHistory`，实际写入与初始绑定检查不在同一事务或互斥区。撤权在两者之间完成时，旧请求仍可写入。 | 绑定导入在实际写入的同一事务或互斥区重新核验当前凭据摘要、账号、车辆及来源范围、撤销和过期；普通未绑定的本地导入保留原有路径。 |
| PostgreSQL | `importHistoryPostgres` 原先没有在导入事务中锁定并重新验证绑定。 | 绑定路径遵循 **车辆归属行 → 绑定行 → 会话锁/行** 的顺序；先核验并持有相应行锁，写入后、提交前用数据库 `clock_timestamp()` 再检查过期。相同时间的撤权若先完成，导入拒绝；导入若已持锁，撤权等待其提交或回滚后再完成。 |
| 内存模式 | `resolveArchiveBinding` 与 `importSessions` 各自持锁，之间存在撤权窗口。 | 在同一原 store 的 mutex 中复核绑定；只暂存当前账号/车辆必要的 session、startedAt 和 nextPublicID，沿用原有合并逻辑，取消或过期时不发布暂存结果。已有路线、费用和其他车辆数据不因失败被覆盖。 |

PG 绑定写入保留调用方请求 context，不再引入此前候选的 25 秒总事务截止。`SET LOCAL lock_timeout = '5s'` 限制每次等待锁，独立的 5 秒回滚 context 用于请求取消后的清理；正常未绑定导入的回滚路径保持原样。锁等待超时、取消及数据库错误走通用 503，缺失/无效凭据走 401，撤销、过期或来源/车辆范围不匹配走 403；不得把无效授权伪装为成功。

事务回滚保护业务行不发生部分提交；PostgreSQL 的 sequence/`nextval` 并非事务性，若失败前曾尝试新增行，序列仍可能前移，不能据此宣称数据库字节或序列完全未变。普通桥只在导入及回执成功后推进游标；其现有轮询对 401/403 仍会记录错误并继续按原间隔重试，不能称作自动停止或自动续权。
