# MateLink 小程序与 App 页面展示规范与地址动态裁剪规则

**文档版本**：v1.0.0  
**生效基线**：微信小程序 v0.6.5+ / Android App Build 103 / v2.1.83  
**相关模块**：
- 小程序端：`miniprogram/src/domain/address_display.ts`、`miniprogram/src/pages/drives/index.tsx`、`miniprogram/src/pages/charges/index.tsx`
- 原生 App 端：`com.matelink.util.AddressDisplayFormatter`、`DrivesScreen`、`DriveDetailScreen`、`ParkedDetailScreen`

---

## 一、背景与设计目标

在日常用车记录中，Tesla 车端与高德/OSM 反向地理编码生成的地址通常为多层级完整行政区划字符串（如 `浙江省杭州市余杭区仓前街道好呷温州小吃泡炸万通中心`）。在移动端列表与卡片上：
1. **视口狭窄与信息淹没**：重复显示冗余的省、市、区前缀导致核心目的地（POI/商户/门牌）被折行或挤压截断；
2. **前后文重复认知疲劳**：同城、同区乃至同街道的日常通勤行程，两端均重复出现相同的行政区划；
3. **驻车场景核心关注点偏离**：用户驻车最关注的是具体停放场所（商场、餐厅、小区、公司），而非重复出现的行政区划。

本规范确立了 App 与微信小程序端**行程起点到终点（A -> B）的逐层消除展示规则**、**驻车位置精简规则**，以及**数据离线秒开与返回防卡顿机制**。

---

## 二、A点到B点（行程起点与终点）展示规则

行程卡片（`DriveItem` / `history-route`）与行程详情卡片（`DriveDetail` / `RouteIndicator`）统一应用以下层级消除策略：

### 1. 核心判定逻辑（自顶向下逐级收敛）

```
[省份比对] -> 相同？ -> [去除省份] -> [城市比对] -> 相同？ -> [去除城市] -> [行政区比对] -> 相同？ -> [去除行政区] -> [街道比对] -> 相同？ -> [去除街道，仅展示详细 POI]
    |                                   |                                   |                                   |
   不同                                不同                                不同                                不同
    |                                   |                                   |                                   |
v                                   v                                   v                                   v
保留完整省份                       保留两端城市                       保留两端行政区                     两端保留各自街道
```

## 三、驻车记录（Parked）展示规则

在行程时间线中，连续两段行程之间插入的驻车卡片（`ParkedItem`）及点击进入的驻车详情（`ParkedDetail`）遵循以下规则：

### 1. 驻车地址展示规则
- **去冗余原则**：驻车必然发生于上一段行程终点或下一段行程起点。若驻车位置包含省、市、区行政区划，**一律去除省市区前缀**。
- **街道后内容优先**：若地址解析包含街道（如 `仓前街道`）且街道后具有具体建筑物/商户/门牌（`detail`），**仅展示街道后面的具体内容**。
  - 例：`浙江省杭州市余杭区仓前街道好呷温州小吃泡炸万通中心` -> **`驻车于 好呷温州小吃泡炸万通中心`**
  - 例：`浙江省杭州市余杭区仓前街道青象传媒杭州精诚电力设备有限公司` -> **`驻车于 青象传媒杭州精诚电力设备有限公司`**
  - 例：`余杭区仓前街道龙泉路杭州精诚电力设备有限公司` -> **`驻车于 龙泉路杭州精诚电力设备有限公司`**
- **保底回退**：若地址本身较短未包含详细 POI（如仅记录到街道或区），则按 `街道 > 区 > 市` 顺序优雅回退，绝不展示空文本。

### 2. 驻车数据指标规则
- **起止电量与压降**：准确读取上一段行程的结束电量与下一段行程的起始电量，展示 `共驻车 Xh Xm, ↓Y 个百分点, 电量变化 -Y 百分点`，并展示新增的 **`续航损失 -Z km`**。
- **能耗与漏电估算**：当缺乏高精度车载 kWh 遥测包时，采用电池百分比与标称电量估算并以 `≈` 标识（如 `净电量变化 ≈0.60 kWh`，`预估消耗续航 ≈4 km`，`待机功耗 ≈367 W`）。
- **待机工况推算**：智能匹配掉电速率，判定车辆状态为 `深度睡眠休眠 (超低功耗)`、`哨兵模式 / 车机唤醒 (常态待机)` 或 `车机活跃 / 驻车保温`。
- **环境温湿度与历史保护**：若驻车期间缺乏历史温度传感器采样，严格展示 `—` 并附带说明“— 表示本段缺少合格的历史观测；不会用车辆当前状态填充过去的数值”，严禁填 0 或借用当前状态伪造历史。

## 四、充电历史指标与明细规则

1. **月度宏观统计全景**：
   - 包含充电次数、充电总电量、总费用、单次均价；
   - 增加能效指标：**平均电价（`¥X.XX/kWh`）** 与 **单次平均充入（`XX.X kWh`）**。
2. **单次充电明细卡片**：
   - 彻底去除“未知”徽标；
   - 区分 `交流`（慢充）与 `直流`（超充），根据充电功率阈值（>22kW）或快充协议自动判定；
   - 显式展示 **单度电价** 与 **平均充电功率**（`单价 ≈ ¥X.XX/kWh · 均功 ≈ XX.X kW`）。
