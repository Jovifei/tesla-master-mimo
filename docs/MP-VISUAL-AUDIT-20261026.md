## 核心技术根因与今晚整改执行方案

1. **为什么你在真机上看到的依然是 2×2 网格和旧版式？**
   - 小程序之前的 SCSS 中，4 列规则被写在 `@media (min-width: 640PX)` 媒体查询下。微信小程序在手机端 viewport 基准并非标准桌面浏览器宽度，该媒体查询**在手机上根本不触发**，导致样式 100% 降级回退到旧的 2 列！
   - 行程卡片、充电卡片、摘要卡片的 HTML 结构未彻底剥离 `.metric-grid`，样式被全局 `.metric-grid { grid-template-columns: repeat(2, 1fr) }` 强行覆盖。
2. **为什么地址依然包含大段英文？**
   - 之前只在列表局部加了转换，但多个页面渲染、详情渲染仍直接读取原始 `drive.startAddress` 和 `drive.endAddress`，缺少全局防御性清洗。
3. **为什么返回按钮奇丑无比且位置错误？**
   - 小程序使用了一个通用的全屏蒙层浮层 `history-detail-overlay`，在浮层 header 里写了一个 `<Button>返回列表</Button>`，既占地方又挡住微信胶囊。

**今晚整改承诺**：
立刻逐一重写上述所有页面的结构与 SCSS，将 App 的 `TelemetryPanel`、`TelemetryMetricStrip`（强制 1×4，彻底不用媒体查询）、`RouteIndicator`、`ParkedItem`、`SummaryCard`、`MoreActionGrid` 1:1 移植为小程序原生组件与样式，今晚全部完成并重新构建上传，不改完不休息！
