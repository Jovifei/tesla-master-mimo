# 经验规则：历史数据必须按资源边界读取

日期：2026-10-02；关联 `RPT-2026-10-02-history-memory-repair.md`。

## 1. 计数不是详情

计数用COUNT、存在性用EXISTS、来源/质量只读需要的列。禁止先调用full-history再len、遍历或裁剪。轻量接口应通过静态SQL边界和大payload集成回归验证，而非只测空库。

## 2. 分页必须发生在装载之前

LIMIT/OFFSET和日期筛选先在数据库执行，再映射当页。对JSON首尾点的提取也要先限定当前页。默认页数有界，服务端页大小上限明确，极大page值先与total比较再乘法。下一阶段采用cursor/revision避免跨请求插入漂移。

## 3. 存储量、累计分配、live heap和RSS是四个指标

9.13MB存储不能推断运行内存。TotalAlloc用于比较分配行为，不代表峰值RSS；合成数据匹配点数也不代表匹配真实压缩率。不能把单查询数KiB说成整个服务器只用数KiB。

## 4. 轻量查询错误不等于空数据

数据库不可用、超时或取消时不得显示0条记录、collecting或要求用户补Tesla授权。错误、空集合、真实零值、未知值必须分开。

## 5. 应用内存有界不等于整个系统安全

COUNT仍访问会话行，JSON端点仍可能触发数据库解压；详情和导入并发仍可放大。应分别测Go堆、RSS、PGCPU/IO和排队时间。保留context、查询超时、事务释放；重负载不能饿死登录。

## 6. 不用数据损失换服务恢复

不删原始点、不把完整轨迹缩成两点、不清App历史。地图派生简化路线必须标记，不改变原始归档。设备ACK只证明指定设备保存指定版本，不代表已备份或所有未来设备可恢复。

## 7. 旧规则不能覆盖新架构

2026-09-27混合架构允许并要求保留Jovi个人TeslaMate完整归档；旧本地-only/两日裁剪文档不是当前删除授权。新存储分层必须先提案、双写、校验、恢复验收，再讨论清理。

## 8. 每层成功独立记账

SOURCE / GO / PG / PERF / DEVICE / DEPLOY / LIVE_TELEMETRY分别记录。268旧基线通过不是274新修复通过；修复分支通过不是生产部署；healthz200不是OOM闭环；归档成功不是Fleet首事件。第五次旧重启原因未核验，不补写成OOM。

本地接手时将这些规则追加引用至tasks/lessons.md、tasks/todo.md与既有Obsidian镜像，保留旧经验和用户未提交内容。网页端本轮未访问本地镜像。
