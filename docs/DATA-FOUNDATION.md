## 来源到页面

| 数据族 | 权威输入与计算 | 服务端／手机保存 | 缺少时的正确解释 |
| --- | --- | --- | --- |
| 车辆身份与当前状态 | 当前用户的 Tesla 授权、车辆绑定和 Fleet／兼容 API 快照。数字车 ID 只在其账号与来源内有意义 | 服务端按用户和车辆保存最新值；App 缓存必须同时校验账号、来源和稳定车辆身份 | 未验证身份不得使用旧车状态、位置或照片 |
| 行程列表与详情 | 完成的 Fleet 会话或 Jovi 个人 TeslaMate 归档；里程、时长、速度、温度与能耗分别按自身证据资格计算 | 服务端有界历史；Room 保存摘要和已取得的详情证据 | 列表有摘要不等于曲线点齐全；仅有 SOC 差不等于已观测 kWh |
| 行程能耗与统计 | 合格净 kWh／合格距离配对后算 kWh/100km；负净回收和真实 0 保留。部分样本必须显示覆盖数 | 服务器原始 receipt 与合同、手机 Room 资格投影 | 不能用未知行程里程稀释有能量样本，也不能把充电能量当驾驶能量 |
| 充电能量与费用 | 电池充入、桩端 AC 输入、储能变化与费用是不同测点；费用来自可信记录或用户补录，不从未知电价推零 | 服务端会话／点位；Room 摘要及本地费用覆盖 | 插枪、短充和 0 kWh 与缺数据分开；默认隐藏短充不代表删除历史 |
| 车内外温度 | 当前温度来自有时间的快照；历史趋势只能取合格的行程／采样时间，不把当前值写成旧驻车曲线 | 服务端字段及历史采样、Room 现有行程温度 | 有当前温度但无历史采样，应显示“实时有值、历史未采集或不合格” |
| 四轮胎压 | 每轮 `bar`、来源和采集接收时间需同车验证；当前值与趋势样本资格不同 | 服务端最新字段；App 通过 Worker 保存合格 Room 样本，趋势读取本地窗口 | 首页显示当前胎压不证明 30 天趋势有合格历史 |
| 驻车详情 | 需对应驻车时间窗内的远端详情与采样点 | 目前该页面主要读取远端；不能假称已具备完整 Room 离线驻车详情 | 不拿首页实时温度或相邻行程均温代替驻车期间数据 |
| 电池健康、固件、地点、天气及其他分析 | 逐项核对接口、观测窗口和外部来源；地图位置仅用当前账号车辆的合格坐标 | 各页面与缓存能力不同，不以通用模型字段推断已保存 | 需说明缺的是授权、上游字段、足够样本、资格还是离线缓存 |

## 当前需要优先关闭的链路

1. 车辆状态的旧 SharedPreferences 只按数字车 ID 缓存；跨账号／来源同 ID 可能错误复用。离线读取必须绑定已验证身份，旧无作用域记录不能猜测归属。
2. 登录刷新发出后若用户退出或换账号，迟到的成功／失败结果不得恢复旧会话或清掉新会话；旧请求也不能自动携新账号令牌重放。
3. 当前状态没有坐标不代表电量、温度或胎压无效；保存资格按字段处理，同时地图坐标保持独立验证。
4. 旧可信归档行程若只有温度字段合格，趋势应按字段、来源与时间窗判断；隔离／伪造／冲突记录仍拒绝。
5. 本机 `allowBackup=false`，现有 Room 历史不等于换机可恢复备份；服务端也不是所有本地胎压、费用调整和详情点的镜像。

## 可以扩展，但不能直接冒充已交付

- Tesla 官方 Fleet Telemetry 列有 `EnergyRemaining`（标称剩余电量，kWh）、`InsideTemp`、`OutsideTemp` 和逐轮 TPMS。当前 MateLink 配置已选择温度与 TPMS，但未选择 `EnergyRemaining`；要新增行程端点能量需先核对车辆支持、逐条真实时间、采样覆盖、储存和跨端合同，并标为估算，不能用短缺采样外推整段行程。
- TeslaMate v4.3.0 新增历史温度看板与车辆排序。MateLink 可借鉴交互，但只有实际桥接的时间序列才能画 App 历史温度；车辆排序可在账号／稳定车辆 UID 范围内作为独立用户设置。
- 已有当前状态字段可更清楚展示电量、续航、温度、胎压、充电功率／电压／电流、车辆软件等；展示前必须在同一响应中验证单位、时间和来源。字段在 Kotlin 模型中存在不代表提供方已上传。

## 空态与验收

不能承诺所有页面永远有数字。没有真实记录时，用图标和具体原因说明“等待首条观测”“历史尚未采集”“本机未下载详情”“费用尚未记录”或“当前账号无权读取”，并给出适用操作；不得填假 0、旧车缓存或演示值。每项修复须穿过 API 解析、身份核对、本地写入／重开、页面消费者与负例；源码、模拟器、当前手机和生产版本各自记录。
