# MateLink 车型展示、地点识别与驻车能耗设计

## 目标

在不改变 `com.matelink`、既有四个一级页面、用户数据或自托管连接方式的前提下，完成以下体验：

1. Dashboard 根据车辆响应中的 `model`、`exterior_color`、`wheel_type`、`trim_badging` 显示对应车型外观图；用户可用自己的相册照片覆盖自动图。
2. 中国大陆坐标显示中文地点，统计页不再以粉色“地理编码 0/50”表达后台状态。
3. 驻车记录如存在实际重叠充电，明确显示“充电驻车”并跳转到对应充电详情；普通驻车保留独立详情。
4. 充电列表内直接修改总价；货币由设置页统一控制，未显式设置的中国默认值为 CNY。
5. 待机能耗按 7 天、30 天、1 年、全部/自定义范围，基于真实停车样本给出 SOC、能量、平均功率、覆盖和归因；数据不足时说明缺少的证据。

## 不做的事情

- 不下载、不打包 Tesla 官网或媒体图库照片；这些素材不具备公开 App 的默认使用授权。
- 不把停车 SOC 变化伪装为 kWh 或瓦数；未达到采样覆盖条件时只显示可观察到的 SOC 变化。
- 不把空调、哨兵或其他原因写成推测结论；没有对应遥测字段时显示“未采集”或“原因未知”。
- 不在本轮接入 Tesla 云端、购买服务器、使用真实 OAuth 凭据或改变用户现有服务器配置。

## 设计与数据契约

### 1. 车型展示与用户照片

Dashboard 新增 `VehicleProfileImage`：

- 自动源：读取现有 `CarData.carDetails` 和 `CarData.carExterior`，映射 Model 3、Model Y、Model S、Model X 的本地原创车型渲染图与外观色。
- 原创素材：使用图像生成工具制作无 Tesla 标志、无官网素材、无商标暗示的本地车型类别渲染图；每张图以透明背景或与现有浅色面板匹配的背景导出，放入 Android assets。
- 自动颜色：外观色来自 API；现有颜色/轮毂/trim 解析逻辑作为自动选择基础。
- 手工覆盖：提供“更换车辆图片”入口，优先可选择“使用自动外观”或 Android Photo Picker 选择用户自己拥有的照片。照片复制到应用私有目录，仅本机使用；重置后删除该私有副本。
- 车型不确定：显示中性原创电动车渲染图、车型文本和“外观信息不完整”，不显示错误车型。

### 2. 中文地点与地点识别

现有 `GeocodingRepository` 变为以缓存优先的国内地点解析门面：

1. 先读取本地 `GeocodeCache`。
2. 中国大陆且已配置高德 Android SDK Key、已取得高德隐私同意时，使用 Android SDK `GeocodeSearch` 逆地理编码；高德回调地址作为中文地址、行政区和城市写入缓存。
3. 高德不可用时，不调用 Nominatim；保留 API 已有地址或显示“未设置高德地点服务”。
4. 地址源只有英文 `street` 且缺少坐标时不能翻译，保留原始地址并标明“来源地址”。

统计页面将原卡片改为：

- 标题：`地点识别`。
- 主文案：`已识别 X 个历史地点，待处理 Y 个`。
- 状态色：低饱和青蓝信息卡；失败/未配置使用中性说明卡，不使用粉色警示外观。
- 只有队列实际执行时展示进度条；队列为空但历史地址缺失时展示配置说明与重试入口。

Cloud 模式不使用客户端高德 Web 服务 Key；将来云端部署时由受控服务端使用运营方高德 Web 服务能力。

### 3. 充电驻车与驻车详情

自托管 Adapter 的 `parked` 响应新增可选 `linked_charge`：

```json
{
  "charge_id": 123,
  "start_date": "...",
  "end_date": "...",
  "energy_added_kwh": 28.4
}
```

- Adapter 以驻车区间与 `charges` 表的真实时间重叠确定关联充电；无重叠时字段不存在。
- Android 保持旧响应兼容：没有 `linked_charge` 的自托管旧 Adapter 或云端响应仍显示普通驻车。
- 普通驻车：使用停车、能量、温度、采样覆盖四块语义卡，使用 Material 图标与现有主题令牌，不再整页灰色参数卡。
- 充电驻车：标题显示 `充电驻车`，突出充入电量与时间，主操作为 `查看本次充电`，直接导航至该 `ChargeDetail`；不额外创建模拟记录。

### 4. 充电总价与货币

- 将 `ChargePriceDialog` 从详情页提取为可复用组件。
- `ChargesScreen` 的每张充电卡中，“修改总价”直接打开该弹窗；保存写入既有 `ChargeCostOverrideStore`，列表立即重新计算费用、图表和汇总。
- 详情页继续复用同一弹窗，保证验证规则一致：有限、非负、允许明确 0 为真实免费，清除则恢复原始来源。
- 设置页保留货币选择；金额始终使用当前全局选择。
- `currency_code` 已明确保存时绝不覆盖；仅旧安装缺少该键时，迁移默认 CNY，不再因存在服务器 URL/API Token 而推断 EUR。

### 5. 待机能耗分析

新建 Adapter 只读端点：

```text
GET /api/matelink/v1/cars/{carId}/standby?from=YYYY-MM-DD&to=YYYY-MM-DD
```

返回每个停车窗口与汇总所需的真实字段：开始/结束、地址、SOC 起止与变化、停车时长、有效采样时长、覆盖率、积分能量、平均/峰值功率、温度、空调活动样本比例、关联充电状态。

窗口规则：

- 必须无驾驶、无关联充电、停车至少 2 小时、SOC 有起止观测。
- 仅在位置功率采样覆盖率至少 80% 时显示 kWh、平均 W 和峰值 W；否则仅显示 SOC 变化与覆盖不足。
- 单窗口可作为“初步观察”；总体结论与个性化建议必须至少 5 个有效窗口并累计 20 小时。
- 空调仅以 `is_climate_on` 实测样本归因；哨兵在当前 TeslaMate 历史无可用字段时显示“未采集”。
- 日期范围：7 天、30 天、1 年、全部、自定义。Android 不再复用包含季节的通用 `AnalysisWindow`，新增 `StandbyWindow`，避免影响其他分析页。

待机页面的信息结构：

1. 时间范围筛选。
2. 一张摘要卡：有效窗口数、停车时长、SOC 下降、kWh/W（有覆盖才显示）、置信度。
3. 归因卡：空调活动、温度、哨兵状态、未知原因，均标明采集状态。
4. 每日趋势和可展开窗口列表；不显示固定容量假设或虚假零值。
5. 数据不足卡：精确列出“当前 X 个合格窗口 / 需 5 个”、“当前 Y 小时 / 需 20 小时”、“功率采样覆盖不足”等原因。

## 实施范围

- Android：Dashboard、车辆图片组件/本地图片存储、GeocodingRepository、统计、Drives/Parked、Charges、Settings 货币迁移、Vampire/Standby、导航、资源与 JVM 测试。
- 自托管 Adapter：停车关联充电、待机窗口端点、Go 单元/HTTP 契约测试。
- 文档：数据字典、用户可见说明、任务台账和 Obsidian。
- 不修改 iOS/Web；不提交 Git、不推送、不新增生产密钥、不操作服务器。

## 验收

- Model Y/3/S/X 自动车型图、自动颜色与用户照片覆盖/重置均可验证；无官方 Tesla 照片或 Logo 被打包。
- 中国大陆坐标在高德可用时缓存中文地点；未配置时不调用 Nominatim。
- `地点识别` 卡能区分处理中、未配置、失败、已完成；`0/50` 有可读解释。
- 停车关联充电时可一跳进入正确充电详情；未关联充电的驻车仍能查看详情。
- 充电列表点击修改总价只出现一个金额弹窗；CNY/USD/EUR 设置切换后全页同步；旧显式货币设置不变。
- 待机页 7 天/30 天/1 年筛选、覆盖阈值、未知原因和空调归因均有 Kotlin/Go 边界测试。
- Android Debug/Release 单测、Go test/vet、`assembleDebug`、`assembleRelease`、`lintRelease`、`git diff --check` 通过；`MissingTranslation=0`，不建立 lint baseline。
- 先在模拟器或专用测试环境回归；仅在 Jovi 单独授权后才用同签名 `adb install -r` 覆盖实体手机，不运行 instrumentation、不清数据。

## 证据边界

本轮可以证明本地/自托管 App 体验和数据规则。真实 Tesla OAuth/Fleet、生产服务器、官方图片授权、哨兵原因归因和历史遥测完整性仍是独立外部门禁，不能由本轮测试宣称通过。
