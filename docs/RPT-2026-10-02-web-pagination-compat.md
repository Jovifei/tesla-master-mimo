# 2026-10-02 Web历史分页兼容补充

此文件补充 `RPT-2026-10-02-history-memory-repair.md` 与 `handoff/codex/NEXT_AGENT_20261002_HISTORY_MEMORY.md`。后端修复之后又完成以下兼容性整改；接手时必须同时阅读。

## 原问题

Web的 `src/api/client.ts` 原 getDrives/getCharges 不传page/show，直接把一次响应当成完整历史。后端改为默认50条有界分页后，旧Web如果继续使用，会漏掉后续历史并影响依赖这些数组的统计。

## 实现

- 新 `history-pages.ts` 串行读取摘要页，每页请求50条，使用服务端实际show与total_pages；没有meta的旧服务按短页终止。
- 稳定ID去重，页码/总数/数据结构校验；空数据不造记录，失败、重复无进展、缺页或页数上限都明确拒绝，不能把部分结果当完整统计。
- 总页数安全上限2000，超限是错误而非静默截断。超大账户后续需要服务器聚合与日期范围查询，不应让浏览器一次持有所有摘要。
- getDrives/getCharges原Promise数组契约不变，实际调用新分页器；连接/API凭据发生变化时丢弃在途旧结果，凭据不写日志。
- 只改变Web历史读取，不重做页面，不修改Android/iOS/小程序；原显式Mock模式保持独立，生产失败不转Mock。

## 验证

本地Node22.16通过13个定向用例：行程/充电各66条4页、无meta旧服务、空库、中途错误、重复页、错误页码、连接变化、非法响应、跨页ID重叠、页上限、总数不一致、实际API入口接线。

这13项使用真实分页模块及接线源码断言，不是浏览器E2E。完整Web干净安装及 `npm run build` 在同分支隔离CI新增执行步骤，最终是否通过以对应HEAD工件为准；不要在未取得该日志前宣称通过。

`npm ci --no-audit` 只用于可复现构建，不构成依赖安全审计通过；本轮没有修改package.json/package-lock或宣称全产品无漏洞。

## 本地发布注意

后端默认页大小改变时，应连同此Web客户端更新进行受控验证；至少验证50条以上行程与充电、统计分母、第二页网络失败显示。Android/iOS常规历史路径使用50条、小程序20条已做源码核对，但本轮没有真机验收。

若Web当前未对用户部署，不要求为后端止血启动新Web站点；记录其未发布状态，之后上线必须带上本补丁。已有Web站点则同轮更新静态资源并验证浏览器缓存不会继续使用旧客户端。
