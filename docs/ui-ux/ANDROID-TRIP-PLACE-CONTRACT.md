# MateLink Android：行程起终点与首页位置

2026-11-12 试用反馈，Jovi 确认：行程 A/B 要展示两个具体地点，例如小区、广场、门店或地标。道路可能很长，不能当作一个点。首页只突出具体地点，点击看车辆位置。

1. **先看原记录。** 起点和终点独立取值。优先保留各自明确的命名地点，移除行政区前缀；不要把「小区」「园区」识别成行政区，也不要用两地的共同前缀决定是否丢掉地点名。没有名称时，可显示原记录的道路与门牌。详情缓存若与同一条行程匹配，可补足列表摘要的地点字段。
2. **非空不代表精确。** 仅有道路或行政区时，可用原记录同一端点的有效坐标，经过现有权限和车辆、账户、来源、记录校验，在显示层细化。优先采用高德返回的建筑物和社区名称；不从周边兴趣点列表任选一个。高德字段见[Android SDK 文档](https://a.amap.com/lbs/static/unzip/Android_Map_Doc/Search/com/amap/api/services/geocoder/RegeocodeAddress.html)。结果到达时再次核对记录和坐标；不覆盖原始回执。
3. **保留精度边界。** 例如「春晓小区 → 青禾广场」；只能确认道路时显示「梅园路（仅道路）」，只有行政区或没有有效地址时显示「具体地点未记录」。不从另一次行程、相邻坐标、其他车辆或账户补地点。首页无名称但有有效坐标时显示「查看位置」，仍可进入地图。
4. **验收看完整链路。** 同一条行程核对列表、详情和详细曲线的 A/B；测试不同道路同一小区、带省市区前缀的地点、门牌、只有道路、缺值和延迟返回后切车。真实地点缺失时不能靠通过格式化测试认定数据已补齐。

底栏「行程」使用每日叠卡；「更多 → 行程历史」保留日期范围和可连续滚动的每日列表。日期、里程、能耗、电量、速度与功率仍以原记录及原计算为准。
