## 总结

截图同时暴露三类问题：

1. 数据有，但被来源、会话、币种或样本资格门拒绝，页面只剩 `—` 或“暂不可用”。
2. 数据只有摘要或稀疏采样，页面没有把“观测/估算/未知”的原因放在用户能快速理解的位置。
3. 数据链路正确，但卡片高度、列宽、文本层级和图表顺序造成内容挤压。

## 数据链路结论

- 充电费用：API/Room `ChargeData.cost`、本地 `ChargeCostOverride`、默认电价估算最终统一进入 `projectEffectiveChargeCost()`。当前横杠主要表示资格拒绝或缺少能量，不代表估算函数从未计算；UI 需要展示拒绝原因和可编辑状态。
- 充电曲线：详情 API 的 `charge_details` 提供 `charger_power`、`charger_voltage`、`charger_actual_current`、`outside_temp`、`battery_level`。`ChargeStatsCalculator.project()` 做时间窗、冲突和有限值过滤；曲线存在资格门，但截图没有把点数和拒绝原因展示出来。
- 行程地图：详情 API 的 `drive_details` 提供经纬度；`DriveDetailScreen` 使用 `observedDriveRouteSegments()` 和 `AmapRouteView`。截图已经证明地图能显示，问题是地图、摘要和详细曲线层级需要更紧凑地组合。
- 行程曲线：速度、功率、电量来自同一批带时间戳位置点；功率为空或接近零时必须保持真实，不得用总能耗倒推成连续功率。
- 地址：现有 `toChineseDisplayAddress()` 只保留地址中已有汉字片段；纯英文地点无法凭字符串安全翻译。应使用 AMap 反向地理编码和本地缓存，并在无结果时保留原文。
- 里程/年度：距离和能耗由 `MileageViewModel` 按有效行程样本聚合，费用由同一批充电费用投影聚合；费用空值是资格覆盖不足，应显示覆盖数而不是孤立横杠。

## 建议修改批次（本轮不执行）

1. 费用状态：增加 `待核实金额` / `暂无合格账单` 展示状态；保存后立即发布本地金额并保留来源未核实说明；补列表、详情、里程、统计四端一致性测试。
2. 地址解析：充电列表/详情统一走经纬度反向地理编码缓存；失败时保留原地址，补中文地址、英文地址、无坐标三组测试。
3. 详情头部：重排开始、结束、时长和费用区域，先固定最窄屏宽的文本边界，再做截图回归；不改 API 或计算公式。
4. 行程详情：保持地图，新增紧凑摘要与曲线入口；对地图点不足、曲线点不足、来源未核实分别给出有限文案。
5. 曲线：保持折线与真实断点；增加功率/电压/电流/温度点数和时间覆盖说明；禁止平滑填补缺失点。
6. 里程/统计：拆分年度卡片布局，修正年化字段命名，费用空值显示覆盖原因；确认 2026 年年度柱不是把所有数据压成单根不可读柱。
7. 首页车辆：只收窄图片容器、上移主体并做资源透明边界回归；不改车辆身份、状态或里程来源。
