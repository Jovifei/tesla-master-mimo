# 胎压重试截止时间复审

本轮完整交互阶段复审发现：`TpmsTrendRefreshController.retry()` 复用失败请求的 `now`。真实 `TpmsHistoryRepository` 把该时间作为 `getVerifiedCollectorInRange(..., now + 1)` 的上界，所以失败与重试之间自然到达并已保存的样本会被排除。用户点击重试不应冻结在旧时刻。

修复直接进入当前实际控制器：保留最近请求的车与七/三十天窗口，但使用重试时钟创建新请求；不改动观测时间、不升级样本资格、不改变 DAO 或历史数据。参数可注入仅为确定性测试；真实 ViewModel 原有 `retry()` 调用使用当前系统时间。

新增 `TpmsRetryWindowTest` 覆盖：默认失败重试实际时钟范围；连续重试仍是最新车辆/窗口但截止时间逐次推进；尚无请求时不能任意选择车辆。保留已有迟到身份/设置、取消重入和来源回归。此发现不是重新声称收到自然 TPMS，也不是历史回填。

本修复提交须重新通过其自身完整 Android、API35 和跨层工作流，旧提交的绿色不替代。最终 PR 回执应以包含此修复的 SHA/tree/parent 为准。
