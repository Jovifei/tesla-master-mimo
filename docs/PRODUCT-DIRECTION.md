# MateLink 产品方向

MateLink 的目标是以可信的车辆数据构建 App、Web 和微信小程序，并为未来硬件留出方向。这里区分长期目标与当前已验证能力；任何平台的源码存在都不等于已发布或与其他端完全等价。

| 客户端 | 长期角色 | 当前工作原则 |
| --- | --- | --- |
| Android App | 原生主客户端，保存合格本地历史、支持离线阅读和设备通知 | 保留原手机数据；每次安装独立核对签名、迁移和实际页面 |
| iOS App | 原生客户端，遵守同一数据语义与主要任务流程 | 按 Apple 平台适配交互；需 macOS 构建和真机验证，不能用 Android 结果代替 |
| Web | **正式长期客户端**，逐步与 App 对齐 | 按页面和数据合同逐项补齐；受浏览器权限与存储限制的能力须明示，不能假装已与原生端等同 |
| 微信小程序 | 轻量访问与体验入口 | 遵守同一来源、计算和身份隔离规则；订阅消息、缓存及平台能力单独验收 |

## 跨端一致的尺度

- 先统一用户任务和数据含义：车辆身份、行程、充电、胎压、能耗、统计、诊断及状态解释。Web 与小程序逐页与 App 核对来源、单位、时间、资格、空态和交互，再决定平台专属呈现。
- 真实零、未知、估算、负净能量和部分统计覆盖必须不同展示；不能用演示数据填补真实链路空白。网络失败时仅展示仍属于当前账号／车辆的合格缓存。
- 令牌、车辆权限和服务端密钥遵守各端安全边界。任何新页面先验证读取权限与跨账号／跨车辆隔离；诊断展示不触发车辆命令。
- 用同一场景核对列表、详情、趋势和摘要；记录每个端实际通过的源码、构建、设备／浏览器和真实事件证据。对齐是持续过程，不是一次宣称完成。

## 未来硬件

保留硬件产品方向。现阶段不指定车辆状态网关、充电外设或其他首款设备，也不创建未经需求和安全验证的原理图。确定具体用途后再定义电源、通信、隔离、车端接入、数据权限、合规与恢复策略，并建立独立原理图工程及样机验证门。

目前的数据来源与保存边界见 [架构与数据流](ARCHITECTURE.md)，详细接口和每阶段证据见 [文档入口](README.md)。
