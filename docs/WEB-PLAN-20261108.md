## 1. 现状核查（先说清起点）

仓库已有 `web_matelink/`（React 19 + Vite + TypeScript + Tailwind 4 + react-router + recharts + leaflet，17 个页面），但它**不是 MateLink 账号体系的网页端**：它的数据层是 TeslaMate 风格的自备服务器模式（用户填服务器地址 + API Token，调用 `/api/ping`、`/api/readyz`），与生产后端 `https://api.teslalink.joviluma.com` 的账号/会话合同完全不同。

结论：**外壳与页面清单可作参考，数据层按生产合同重建**。这不是推倒重来——页面结构（仪表盘、充电/行程列表与详情、统计、里程、电池健康、哨兵、软件版本等）与 MateLink 的信息架构大体对应，可逐页迁移到新数据层。

## 2. 目标与边界

- 网页版是继 Android App（第一）、微信小程序（第二）之后的第三个客户端，共用同一生产 API（现版本 api-b9259501，含车辆唤醒修复）、同一批数据合同（扩展字段、附近充电电价/停车、16 条命令目录与授权门控、配对分级 phase 等，以小程序刚完成的对齐结果为口径基准）。
- **红线不变**：绝不收集/存储 Tesla 账号密码；登录走官方 Tesla OAuth；车辆命令只展示后端授权结果，执行仍受后端逐条授权与全局开关（JOURVOLT_COMMANDS_ENABLED 默认关）约束，网页版不启用任何服务端开关。
- 网页版不部署上线，除非所有者单独批准（见第 7 节）。

## 3. 登录方案（无需后端改造）

后端已具备浏览器可用的登录链（与 App 同款）：

1. 浏览器跳转 `GET /v1/auth/tesla/start` → Tesla 官方登录/授权；
2. 回调落回后端，后端保存授权并发一次性 **login ticket**（2 分钟有效）；
3. 网页以 ticket 调 `POST /v1/auth/exchange` 换取会话；
4. 后续请求带会话调用 `/v1/*`；`POST /v1/session/refresh` 续期、`POST /v1/session/logout` 退出。

待 W1 开工时核对的细节：生产是否启用邀请码门（`/v1/auth/invite/validate|claim`）作为 OAuth 前置步骤——以 App 当前引导顺序为准，网页版照抄。会话只保存在浏览器侧（内存 + 刷新令牌），Tesla 凭证永不经过网页代码。

## 4. 信息架构（与 App/小程序同构，桌面优先）

- 登录/引导（Tesla OAuth + 邀请门如启用）
- **仪表盘**：状态 Hero、位置卡（地址/围栏）、附近充电（电价+停车+导航）、最近行程卡、远程控制区（授权门控与 App 一致）
- **充电**：列表（筛选/月度汇总）+ 详情（五曲线内联）+ 当前充电
- **行程**：列表 + 详情（速度/功率/电量/海拔分组、路线图、驻车详情）
- **分析**：统计、电池健康、费用、续航、待机能耗、温度历史（行程口径）、胎压（当前值+本机不可得的历史以服务端数据为准，无则如实标注）
- **我的**：账号、车辆、配对诊断、分时电价、设置、关于

布局：桌面宽屏用左侧边栏导航 + 内容区（曲线、地图在宽屏下比手机更易读，是网页版的天然优势）；窄屏自动收为顶部栏 + 单列，不单独开发移动版。

## 5. 设计系统（苹果风，与小程序同一套视觉语言）

- 直接采用小程序已落地的 Apple 设计令牌（系统背景、Inset Grouped 分组卡、发丝线分隔、系统色、圆角与字阶），映射为 Tailwind 4 主题变量，三端共享同一视觉口径；
- 大标题导航、卡片分组、克制的色彩与动效；支持 `prefers-color-scheme` 深色模式；
- 字体用系统字体栈（-apple-system / 苹方优先），不引外部字体文件。

## 6. 技术要点

- 沿用仓库现有技术栈（React 19 + Vite + TS + Tailwind 4 + react-router）；数据层新写 `src/api`（对 `/v1` 合同，类型与小程序 `services/types.ts` 同源同义，手工对齐不共享代码——两端工具链不同）；
- 图表：优先评估 recharts（已在依赖中）的体积，不合意则换轻量 canvas 方案，W1 定版；
- 地图：默认高德 JS API（国内坐标 GCJ-02 与 App/小程序一致）；**需要所有者侧提供/申请高德 Web JS Key**（或在 W1 核对现有 Key 是否可复用）。Leaflet+OSM 仅作开发期占位，不进生产（坐标系不一致）；
- 测试：沿用仓库 web 侧现有测试方式并按页补齐关键合同测试；每阶段门禁为 `npm run build` + 测试全过。
