## 问题

原趋势容器以一次性 stdin 获取凭据且重启策略为 `no`。Docker 或电脑重启后，它无法自行重新接入，后续样本不会继续上传。原桥使用可恢复的 Docker 重启策略，但其最大已确认行程编号不能证明每条归档均存在；趋势桥不能靠它跳过服务端来源校验。已处理编号之后补写或更正的旧源记录，也不能通过现有递增游标发现。

## 候选修改

保留原桥现有凭据和趋势独立游标；仅启用可选配置时，原桥在独立私有卷上的 Unix socket 提供内存中的凭据。趋势服务校验双方 Linux UID、socket 文件与目录权限及来源作用域后读取，拒绝从自己的环境继承凭据。趋势容器对原游标目录只读挂载，趋势状态使用明确指定的既有独立卷；启动时检查原挂载只读并拒绝相同状态目录。原桥无法建立 socket 时继续其原有归档工作。

首次原状态尚未生成、源数据库暂时无法连接或原桥 socket 暂不可用时，趋势进程等待；服务端 5xx、408、429 和网络故障保留冻结批次并等待后重试。其他 4xx 停止上传并在独立趋势卷写入状态标记；正常重启仍停发，须查明原因并在授权续绑或解决冲突后明确恢复。只有服务端回执校验通过才推进趋势游标。

## 限制与发布条件

1. 当前 `8d3da22` 对“归档尚未到达”可能返回 409；已验证但尚未部署的 `b11bae0` 才能对此场景返回可等待的 503。必须先验证并部署兼容服务端，才能启用可靠的自动等待。
2. 续绑需用户授权并让原桥使用新的同作用域凭据；状态标记不会因为编辑配置文件或 Docker 重启而自动清除。请保留状态，审查冲突和凭据后再执行明确恢复。
3. Docker Desktop 当前随用户登录启动。容器自身的 `restart: always` 不能让未启动的 Docker 自动运行，也不能采集设备关闭时未产生的源数据。旧编号后补或修正未实现自动回扫。
4. 如果持久化停止标记失败，进程停发并记录故障；若在标记持久完成之前发生强制终止，下一次启动可能再次发送一次冻结请求。此窗口不能描述为绝不重试。
5. 状态卷必须先准确识别并确认与原桥来源一致；启动新趋势服务前停掉使用同一独立卷的旧趋势进程。绑定权限、源库只读角色、socket 卷访问边界和生产后端需另行预检。不得删除、重建或重置任一现有游标。

## 后续：安全续绑后自动恢复的身份前提

v2 自动续绑恢复已实现于本地候选，但旧 v1 状态仍需一次人工授权迁移。现有 enrollment 的 `scope_fingerprint` 仍只覆盖车辆与来源；安全证明来自独立 binding-identity 接口和 v2 状态，而不是 token 字符串或车辆/来源近似。当前候选对 401/403 仍持久停发，对 409 冲突同样停发。

已实现服务端接口：直接在数据库核验有效 token、未撤销、未过期、车主和完整车辆来源后，返回由随机 binding 行 ID 与账号、车辆、来源组合计算的版本化 HMAC 指纹，不返回这些原始身份；同一行的授权续期保持指纹，重新绑定或跨账号变更会改变。桥在独立状态锁内保存指纹；旧状态没有可信身份时保持停发，不能由新 token 自行认领。

自动恢复只使用强制携带预期绑定指纹的 v2 导入路由，并在同一数据库事务中锁定和复核绑定，不能只在发送前调用一次身份接口，也不能自动回退 v2 到 v1。候选测试覆盖绑定到期、撤销、车主并发变更、跨账号/车辆/来源、状态损坏、旧服务和错误回执；仍须完成真实重启与发布验收。409 永不因 token 变化而自动放行。
