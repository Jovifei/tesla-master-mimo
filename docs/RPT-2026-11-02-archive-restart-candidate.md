## 问题

原趋势容器以一次性 stdin 获取凭据且重启策略为 `no`。Docker 或电脑重启后，它无法自行重新接入，后续样本不会继续上传。原桥使用可恢复的 Docker 重启策略，但其最大已确认行程编号不能证明每条归档均存在；趋势桥不能靠它跳过服务端来源校验。已处理编号之后补写或更正的旧源记录，也不能通过现有递增游标发现。

## 候选修改

保留原桥现有凭据和趋势独立游标；仅启用可选配置时，原桥在独立私有卷上的 Unix socket 提供内存中的凭据。趋势服务校验双方 Linux UID、socket 文件与目录权限及来源作用域后读取，拒绝从自己的环境继承凭据。趋势容器对原游标目录只读挂载，趋势状态使用明确指定的既有独立卷；启动时检查原挂载只读并拒绝相同状态目录。原桥无法建立 socket 时继续其原有归档工作。

首次原状态尚未生成、源数据库暂时无法连接或原桥 socket 暂不可用时，趋势进程等待；服务端 5xx、408、429 和网络故障保留冻结批次并等待后重试。其他 4xx 停止上传并在独立趋势卷写入状态标记；正常重启仍停发，须查明原因并在授权续绑或解决冲突后明确恢复。只有服务端回执校验通过才推进趋势游标。

## 后续：安全续绑后自动恢复的身份前提

目前自动续绑恢复**尚未实现**。现有 enrollment 返回的 `scope_fingerprint` 仅包含车辆与来源，不包含账号；本地状态也没有原账号或绑定身份。因此仅比较新旧 token 指纹与车辆来源，不能证明新凭据仍属于原账号。当前候选对 401/403 仍持久停发，对 409 冲突同样停发。

可选服务端设计：新增只读的受限凭据绑定身份接口，直接在数据库核验有效 token、未撤销、未过期、车主和完整车辆来源后，返回由随机 binding 行 ID 与账号、车辆、来源组合计算的版本化不可逆指纹，不返回这些原始身份；同一行的授权续期应保持指纹，重新绑定或跨账号变更则改变。新客户端首次创建待传批次之前，须在独立状态锁内保存可信指纹；旧非空状态或旧停止标记没有可信身份时需先完成原账号归属核验，不能让新 token 自行证明旧数据归属。

自动恢复必须通过新的、强制携带预期绑定指纹的导入路由，并在同一数据库事务中锁定和复核绑定，不能只在发送前调用一次身份接口，也不能回退旧导入路由。服务端与桥均须覆盖绑定到期、撤销、车主并发变更、跨账号/车辆/来源、状态损坏、旧服务、错误回执和断电重放；409 永不因 token 变化而自动放行。此部分仅为设计，尚未更改或测试服务端代码。
