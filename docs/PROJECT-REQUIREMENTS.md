## 一、核心态度与开发作风（绝对红线）

### 1. 严禁虚假汇报与盲目假设
* **禁止以“单元测试全部通过”替代“实际可用”**：
  单测（Vitest）验证的是函数的逻辑契约和 Mock 状态，绝不代表真实运行时、UI 渲染、真实样式、微信运行时 API 和服务端通信完全正常。
* **严禁在未亲眼通过界面确认的情况下声称“已完成”**：
  不能仅因编译命令 exit code 为 0、或代码上传成功，就假定小程序功能完好。必须有具体的界面渲染证据。

### 2. 凡事先自我验证，再向 Jovi 交付
> **“你下次所有的问题，你自己验证好，再让我执行。”**
* 开发者 / Agent 拥有微信开发者工具 CLI、自动化接口（Automator / `wechatide`）、ADB 真机通信等全套控制能力。
* 遇到报错、配置异常、编译问题，必须在本地自行定位根因并验证修复，严禁在未确认修复效果前盲目向 Jovi 索要扫码或要求 Jovi 充当“人肉测试机”。

## 二、生产网络配置与通信要求

### 1. 唯一合法云端通信入口
所有小程序面向生产环境的构建，**唯一的 API 入口**必须为：
```text
https://api.teslalink.joviluma.com/
```
* **Auth Host**：`auth.teslalink.joviluma.com`（用于 Tesla 官方授权与 App Link）。
* **生产服务器 IP**：`120.55.64.11`。
* **生产云 API upstream**：服务器本地 `127.0.0.1:18090`。

### 2. 严禁出现的陈旧与禁用地址
代码、构建脚本、默认回退中**绝对禁止**出现或依赖以下地址：
1. `https://api.jourvolt.com/`（历史废弃域名，严禁用于当前版本）。
2. `http://192.168.0.104:18080`（历史局域网自托管调试地址，严禁作为生产出口）。
3. `198.18.x.x`（本地网络代理 TUN / Fake-IP 虚拟地址，不作为真实网络可达证据）。

### 3. 自托管入口（502）的明确认知
* `https://teslalink.joviluma.com` 对应服务器本地 `127.0.0.1:18080`，当前状态为 **502 Bad Gateway**。
* **原因**：根据《架构决策路线三（Tesla Fleet 多租户 + 本地数据）》，自托管 Adapter 容器已正常停止，该项目未运行任何容器，不提供外部服务。
* **要求**：小程序端**绝不**尝试连接该自托管入口，更严禁擅自修改服务器配置或替换证书试图“修好”该 502。

## 三、构建与工程完整性要求

### 1. 根目录与配置规范
* 微信开发者工具打开的工程根目录为 `miniprogram/`。
* [project.config.json](file:///E:/project/tesla_master/miniprogram_Weixin/miniprogram/project.config.json) 中必须包含明确的 `"miniprogramRoot": "dist/"`。
* 严禁让开发者工具在 `miniprogram/` 根目录下找 `app.json`。

### 2. 编译期常量注入保障
* Taro 小程序在编译时通过 webpack `defineConstants` 将环境变量固化注入。
* `config/index.ts` 必须具备生产 API 地址的安全兜底，严禁使 `TARO_APP_API_BASE_URL` 编译为空字符串 `""`。
* 每次打包后必须对 `dist/common.js` 执行关键字抽检，确保生产 API 已经被确凿编译进产物。
