# MateLink 验证与发布门

每份结论都要写明分支、完整 SHA／tree、测试环境、原始结果和未验证项。绿色源码检查是必要证据，不能替代用户手机、Tesla 自然事件、微信体验版或生产环境。

| 层级 | 可声称的结论 | 仍需另证 |
| --- | --- | --- |
| 源码／合成数据 | 指定输入、身份与计算合同通过 | 真实车辆、真实用户历史 |
| 隔离数据库与模拟器 | 迁移、Room 重开、故障注入及页面可用 | 物理手机原有数据可恢复 |
| 固定 SHA CI | 同一提交的 Android、Go／隔离 PostgreSQL、Web／小程序、TLS、安全审计结果 | 已安装版本或线上已部署版本 |
| 物理手机 | 同签保数据安装、启动及实际页面核对 | 自然 Fleet 新事件、多人长期稳定性 |
| 生产／提供方 | 实际部署修订和官方返回的合格观测 | 其他账号、其他车辆和未来事件 |

## 每阶段至少检查

1. 数据来源：账号、稳定车辆 UID、来源实例和记录 ID、真实时间窗、单位、null／零／负值、估算标签；列表、详情、统计与缓存使用同一资格口径。
2. 通道安全：Tesla 官方授权、服务端租户检查、正常 TLS、敏感日志与缓存隔离；诊断查看不增加无关遥测请求或车辆唤醒。
3. 真实消费者：API 解析 → 本地持久化 → 关闭重开／离线 → 列表／详情／趋势／通知；补成功、迟到、重复、撤销、中断和跨账号负例。
4. 客户端：Android 双变体单测、lint、R8、隔离模拟器；小程序测试／类型检查／WeApp 编译；Web 测试／正式构建。仅声明实际运行的项目与结果。
5. 发布：同一 SHA 的完整 CI 和制品哈希；Android 包名、版本、签名与现装包一致。结构迁移须有可实际恢复的备份，不能把旧 APK 当成数据库备份。

生产服务升级、主分支合并、手机覆盖安装、微信上传和用户数据迁移分别走各自验收。未取得完整证据时保留 Draft 或候选状态，并在交接中写明具体阻断。Android 物理设备操作详见 [设备规程](SOP-ANDROID-DEVICE-DEPLOYMENT-AND-VERIFICATION.md)；云端授权和接口见 [JourVolt 合同](JOURVOLT-CLOUD-API-CONTRACT.md)。
