## 根因与处理

| 问题 | 发现 | 修复候选 |
| --- | --- | --- |
| 充电量和预估费用不可见 | Fleet 存在同一会话内的计数器差值，但会话首尾没有完整观测；旧 API 未给这段证据提供可用覆盖率，App 将完整能量保持未知，也无法据此估价 | 服务端保留完整会话值为未知，校验来源、时窗和字段后发布真实子区间覆盖率；App 独立展示已记录电量及近似费用，手动金额优先 |
| 来源说明占据页面 | 历史未关联说明和默认电价说明在页面常驻或反复弹出 | 说明改为确认一次的提示；账号、车辆和来源变化时未关联说明重新提示；实际同步失败仍保留 |
| 日期筛选占用空间 | 充电和行程页顶部使用多枚筛选按钮 | 日期下拉移至摘要右上角；充电默认近 30 天、行程默认近 7 天，保留全部时间和自定义日期 |
| 地点英文或未知 | 地点菜单直接显示原始英文；部分记录自身没有坐标 | 菜单复用已有中文格式化器并支持中文搜索；缺少坐标时保留未知，不用车辆当前位置猜测历史地点 |
| 坐标可能跨响应拼接 | 同一会话的新旧响应分别只有经纬度中的一轴时，旧代码可能拼成不存在的坐标 | 按完整坐标对择优，保留来源及会话身份栅栏 |
| 首页离线快照 | 云端车辆列表临时失败时，旧逻辑要求新鲜车单才能读取已保存快照 | 同一已验证账号、车辆和来源下，仅在非授权型暂时失败时展示历史快照；不用于写入或定位 |

## 后续问题：接入提示与 Fleet 地点

- `NOV01-ONBOARDING-PENDING`：`StartDestinationViewModel` 会将同账号尚未完成的接入状态导向 Tesla 接入页，点击继续后待处理状态仍保留。后台恢复可能转为真实 401/403、配对要求或阻塞状态；现有首页对缺少车辆 ID 的权限提示覆盖不足。不能简单跳过接入页、伪造 READY 或清除状态。后续需协调启动快照与恢复状态，并覆盖权限失败、车主确认、账号切换和迟到响应。
- `NOV01-FLEET-LOCATION-WINDOW`：Fleet 位置事件可能迟到，旧采集逻辑没有按充电起止时间筛选位置。API `403aa6c` 在采集、列表及详情读取处检查 Fleet 点的同会话时间和有效坐标；归档旧记录规则保持不变，其缺失日期可能曾被代填，不能宣称逐点时间均已核实。生产基线及 App 分支分别在隔离 PostgreSQL 15 通过 591/488 个测试事件和 `go vet`；生产只读预检后定向发布，内部/公网 readiness、Fleet telemetry、未授权 401 与其余 15 个运行容器状态核验通过。生产 PostgreSQL 16 的真实迟到位置样本仍未验证。
- `NOV01-FLEET-LOCATION-MISSING`：充电开始之前的 Location 未用于初始化充电会话；位置配置按变化触发，车辆静止时不保证再收到点。Tesla [官方公告](https://developer.tesla.com/docs/fleet-api/announcements)说明部分固件支持字段定期重发，是否适用于当前车辆及其隐私、流量和能耗影响仍需验证。10 月 31 日原始 Location 事件是否到达未证实，不能据此推断历史坐标。
- `NOV01-CHARGE-REFRESH-FEEDBACK`：build81 真机下拉刷新时先显示缓存，刷新提示可能随后消失；代码审查发现缓存发布和其他筛选更新会提前清除刷新状态，且超时正文被当作错误键而误显示为一般缓存警告。build82 候选仅调整充电页刷新状态及错误键，不修改共享历史仓库或身份栅栏，需回归和真机确认。
- API `403aa6c` 上线后，针对当前车辆的充电历史首分页做了限定身份的只读 `EXPLAIN ANALYZE`（数据库端 5 秒超时）：执行约 331 ms、规划约 30 ms，未见 SQL 兼容错误；没有输出记录、坐标或身份。手机 HTTPS 健康接口返回 200、缓存提示随后消失，但没有逐条 HTTP 成功日志，不能据此声称每次历史请求都已成功。
