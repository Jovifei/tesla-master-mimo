# 月柱数值、最高速度口径与日期边界

## 症状与证据

用户要求月柱上直接显示次数、距离和时长，并明确速度/月的含义。现场只读验收确认柱形存在但数值仅点击后出现，距离纵轴的 `1k` 没有单位。源码 `BarChartData.displayValue` 已有正确文案，却未被绘制。`DrivesChartPage` 原本就取每桶 `maxSpeed`，不是平均速度；此次只明确标题，不把缺失的列表速度补成零。

继续核查实际 ViewModel 发现两个独立日期错误：分组只接收开始日，结束日一律取系统今天；周图还把筛选开始所在的不完整周跳到下一周。因此自定义历史范围会多出无关日期，部分周的已筛选行程会漏画。API 查询已经使用注入 Clock 的时区，旧图表解析则取系统时区，测试/配置不同时会在午夜跨桶。

## 最小修复与数据口径

- `DrivesViewModel` 调用实际 `calculateDriveChartData`，传入选定开始/结束日、Clock 的今天及请求时区；结束日包含当日。首个部分周保留原周起点，但只统计选定日期内行程。缺省结束日才用今天。
- 每条行程按开始日在请求时区归桶，跨月行程不拆分。质量与距离筛选仍在原调用位置，距离/速度保留 API 已返回的单位数值，时长仍是现有整数分钟。此片不修正既有逐条分钟截断损失。
- `InteractiveBarChart` 新增默认关闭的月柱数值开关，月图实际启用。数值和点击提示使用同一个 `displayValue`；真实零可见，未知最高速度仍无观测柱。其他共享调用不自动开启月柱数值。
- 实测月份、数值和纵轴文字尺寸，留出上下标签空间；密集月份横向滚动而不压缩重叠。绘制与命中测试使用同一几何；tooltip 在可见窗口内钳制，滚动或字号/尺寸变化清掉旧选择。
- 行程纵轴写明 km/mi 或 km/h/mph，时长标题注明小时:分钟；速度标题写明每日/每周/每月最高速度。图种圆点保留直接点击入口和可访问名称，避免只有内层横滚手势可用。

## 验证与边界

基线为原分支 `bcc4b2a69b61d9facfe27c34bb880f166bcf8a86`。同一组 13 个日期/统计用例，对提取的原实际分组函数运行得到 12 个失败；最终实际分组函数 13/13 通过。原函数提取仅把 Android 周标题资源调用换为同参数文案回调，未修正其结束日、周起点或时区逻辑。此红绿证据并不说明原最大值算法错误。

另有 6 个实际像素几何函数用例，覆盖窄屏密集月份、长数值、大字号上下留白、横滚后同柱命中、超宽 tooltip 的非负边界、默认调用不强制月柱宽。共 19 个便携 JVM 测试通过，使用真实 DriveData；只有 Moshi 注解和 ApiDataMeta 为测试边界替身。实际 VM 调用、月图开关、空速度处理另作源码核查。

7 个 Kotlin 文件通过 PSI 语法检查，两份资源 XML 解析和 `git diff --check` 通过。这些不等于 Compose 类型检查或完整 Android 构建：云端没有 Android SDK；后续必须在精确源码上完成本机编译、单测、Lint、APK 和手机视觉/交互验收。重点检查中文跨年月份、最大字号、窄屏、横滚后选点、边缘横滑及直接图种切换。版本与安装包尚未升级。

## 不重复走的错误路径

不要只替换 tooltip 文案而遗漏常驻绘制；不要仅按柱数压缩标签；不要用过滤后的序号重建日期；不要把 API 单位再乘一次转换系数。更新月图文案不能补齐云端硬编码 `speed_max=null`，也不能以同一点 SOC 推导零消耗。

最高速度持久摘要、充电输入 kWh、精确时长、驻车真实性查询、44 充电汇总及历史字段补齐各有独立范围和验收；本片不执行生产部署、数据库变更或真实历史回填。经验入口见 [历史源链核查](RPT-2026-10-04-history-source-audit.md)。
