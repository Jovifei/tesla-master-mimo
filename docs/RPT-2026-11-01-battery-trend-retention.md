# 2026-11-01 电池趋势缺失与用户数据保留

## 现象与版本

- 发现日期：2026-11-01；手机当前 App 2.1.62 / build81（源码 `debf631`），生产 API `403aa6c`。Jovi 的旧截图显示 2026-07-09 至 2026-10-29 的 110 个有效续航样本；当前手机实屏显示“暂无有效的电池趋势观测”。
- 只读查询本机 TeslaMate 数据库：当时有一个车辆作用域、476 条完整行程，其中按页面现有 SOC、额定续航和温度条件有 110 条合格样本，日期恰为 2026-07-09 至 2026-10-29。恢复原采集服务后又自然出现一个合格记录；**历史样本有来源证据，没有证据表明覆盖安装删除了这些源记录**。截图数值不是回填数据。
- 依据实际桥配置的来源实例、来源车辆与云车辆作用域，对比来源记录及起止时间的哈希：旧 110 条样本全部与同一云账号下的归档行程精确匹配。稍后本机全部 477 条完整行程也均找到对应的同作用域、同记录、同时间窗云端归档；这只证明身份对应，不证明趋势字段已经上传。
- build79/build81 的 Room 数据库版本相同，历次安装使用同签名覆盖，首次安装时间不变；这说明没有卸载重装，但不能仅凭安装时间断言每条手机数据未变化。系统备份被关闭，现有摘要导出也不是可完整恢复原始样本、详情和手工费用的备份。

## 数据链路原因与恢复方向

电池趋势从每条行程的起点或终点 SOC、同车行程的额定续航及室外均温计算，需要至少 10 条合格样本且覆盖 30 天。实际生产云端行程接口返回 `range_rated=null`，同时缺少可验证的温度单位；现有归档桥没有上传这些趋势字段，因而云端行程存在也不能据此生成原曲线。自托管和云端 Room 按来源及车辆身份分区，不可按数字车 ID 简单混合。

只读聚合确认：历史额定续航来自 TeslaMate `drives.start_rated_range_km/end_rated_range_km`，SOC 来自该行程同车起止位置，温度来自 `drives.outside_temp_avg`。多数旧起点 position 自身没有 rated 字段，不能因此丢弃行程摘要，也不能伪造 rated 的单独观测时间。

候选建立独立、受原归档绑定约束的趋势证据和独立回填进度；按来源实例、来源车辆、来源记录及时间窗校验，完整一致才幂等追加，冲突不覆盖。新通道不得修改现有行程/充电原记录、费用、轨迹或生产桥游标；App 按完整账号、来源与车辆身份读取并保留已验证样本。**截至本次记录，候选尚未部署，尚未对真实数据回填，也未完成手机恢复验收。**

## 哪些数据需要保留

| 数据 | 保护原则 |
| --- | --- |
| 登录会话、车辆来源设置、用户手工费用 | 覆盖安装与同步不得清除；迁移中断、格式异常或冲突时保留原始记录，不用远端估算替代用户输入。 |
| 源行程、充电记录、额定续航/SOC/温度原始证据、真实曲线点 | 保留原来源和同车同记录身份；空、部分或单位未知的响应不能抹掉可验证历史；不得将不同车辆或来源的样本拼接。 |
| 由真实证据计算的摘要与趋势 | 同身份可信新数据可重新计算；同步失败或样本不足时应保留可验证的旧结果并标明缓存，不能把估算称为实测。 |
| 测试样本 | 仅使用隔离数据库和模拟器的合成数据；不能写入用户历史或代替真实样本。 |

## 其他已发现风险与状态

- 设置里的“重新同步”原实现会先删除本车历史摘要和聚合，再请求远端。没有证据表明 Jovi 按过该操作；候选已改为保留已有数据并重新检查历史，31 项相关定向及本候选全量单元测试通过，真机验收待完成。
- 旧版手工总价从 DataStore 迁移时，损坏或部分无效 JSON 可能被静默过滤后删除原文。候选改为保留原 JSON，合法项幂等迁移，异常/冲突不标记完成；真实 Room + DataStore 合成回归已通过，尚无证据证明用户手机发生该问题。
- 电池页面的可用旧趋势可能被同身份的零样本刷新覆盖；候选按经过验证的身份保留缓存并隔离切车，46 项定向及本候选全量单元测试通过，真机待验。
- 同来源同记录连续稀疏响应可能使旧 SOC、续航和温度原始证据不可再读；真实 Room 合成测试已复现，build82 工作树候选按身份、单位与时间窗保留原回执及可验证字段，早先数据保护定向 112 项、后续相关定向 116 项及本候选全量单元测试通过，真机待验。无原始凭据的旧数据不能伪装成供应商回执；不同数字 ID 缺乏可信映射时可能并列显示，不能仅凭时间合并或判断重复。
- 行程与充电原始回执冷归档候选分别限制 64 MiB；某一类别容量耗尽时该类别整批更新回滚，保留旧记录并显示警告，另一类别有独立配额。回执归档不占用户曲线缓存配额，但仍共用设备实际存储；满额后该类别的新更新需后续处理。

## 尚未解决的边界

- 电池趋势 GET 单次读取上限 10,000 条；超过此规模时的完整读取方案仍需验证，不能称为无限读取。
- 行程自动能耗详情在同一刷新周期遇到 503 或超时时，停止该周期后续网络详情请求；下一次前台刷新重新获得预算，已尝试项目仍受尝试标记及手动刷新限制。已有本地证据应保留，不能宣称 503 期间新行程立即补全。
- 源端在独立回填游标推进后才补充或修正的旧证据，尚无已验证的自动重新采集方案；桥重启后的受限凭据安全注入也仍需解决。两项均不能靠宣称回填成功来掩盖。

## 原始采集环境

本机 Docker Desktop 因旧运行时套接字无法访问而无法启动。已将仅含零字节旧运行时项的目录改名保留并创建新的运行目录，未删除 Docker 数据库、容器卷或归档游标；随后按原自动启动配置恢复了多个现有容器。TeslaMate PostgreSQL 只执行只读字段与聚合查询，未输出账号、车辆标识、坐标或原始位置。
