## 已定位的数据路径

1. 源桥在 `deploy/teslamate-home-docker/archive-bridge/db.go:32` 查询源 `charging_processes` 的汇总能量，并在 `:150` 解码充电点；源记录以 `teslamate:charging_process:<源记录号>` 表示。当前样本对应的 archive 已在云端找到，不是“源端完全没有这次充电”。
2. 生产列表在 `deploy/jourvolt-dev-mock/history_bounded_read.go:188` 读取该云会话，并在 `:143`、`:576` 从其充电点提取有效首末 SOC。只有 archive 的绑定身份能够直接对应此次源记录；local_import 没有这项直接来源凭据。
3. 历史手机上传路径在 `android/app/src/main/java/com/matelink/data/sync/SyncRepository.kt:407`、`:480` 将本地充电汇总上传为 `local-charge-<本地 chargeId>`，携带汇总能量和空 route，未携带充电点及源实例身份。最初引入该上传的历史提交 `318e2420` 已有这一客户端 ID 形式，但这不证明本次数据一定由该版本或该设备写入。
4. `deploy/jourvolt-dev-mock/telemetry_import.go:35`、`:215` 将普通导入的客户端 ID 与账号、云车、记录类型做作用域散列；`:472` 的旧导入入口刻意忽略 archive 作用域字段。此次两条 local_import 的来源实例、来源车辆、来源记录字段均为空，质量原因是 `local_import_summary_only`。历史数据库迁移曾使用这一标签，它不能证明本次上传者或源实例。
5. 只读核验将对应 archive 的源记录数字代入当前 `local-charge-<数字>` 规则并按作用域重算，两组结果均不等于实际 local_import 内部 ID。这只否定当前规则下的简单数值 ID 对应假设；旧算法、中间重编号或其他导入路径仍不能排除。
6. `android/app/src/main/java/com/matelink/data/api/models/EnergyModels.kt:132` 与 `ChargeModels.kt:56`、`:165` 不把没有合格合同的 `local_import` 标量直接提升为完整充电量；`ChargesScreen.kt:725` 消费合格电量与 SOC，`ChargeCostProjection.kt:135` 在没有手工费用或可用账单时依据合格电量估算。**如果**手机空卡对应上述 local_import，这些规则与其空电量、空 SOC 和无法估价的现象相符；目前尚未证明手机卡与该云记录的 ID 对应。

## 修复方向

- 先通过合法、只读的原始 API 回执或设备已有身份凭据，确认两张手机卡分别对应哪个公开列表 ID、来源、来源实例和时间窗；不要清除缓存、要求重新登录或重放既有历史来取得结果。
- 不能根据同一分钟、时间误差、相等能量或唯一候选自动合并，也不能把 local_import 的未验证标量直接当作完整电量。需要来源记录的明确关联：例如可验证的原始设备回执，或经授权的映射同时绑定账号、车辆、来源实例、来源车辆和源记录。缺少关联证据时保持两条记录，问题继续开放。
- 只有来源映射和两条记录均可核实且无歧义时，才考虑在展示投影中折叠为一条，以合格 archive 记录显示真实 SOC 和能量；保留两条原始记录、各自 ID 和来源，不重写数据库或伪造原始回执。列表、摘要、过滤、分页与详情需使用一致的经过验证的投影规则，避免折叠后仍重复计数，或另一条不在当前页时错误隐藏。
- 手工费用必须先按原车、原 charge ID、来源及时间窗查找。`ChargeCostProjection.kt:13`、`:27`、`:160` 的身份约束意味着直接隐藏旧卡或直接迁移其费用都可能使用户输入消失或串到别处。仅在已验证映射下引用唯一、币种一致的原手工金额；多笔冲突、币种不符或凭据不足时保留原值并标记待处理，不静默覆盖。无有效手工费用及真实账单时，才按实际可用的用户电价估算。

## 必要回归负例

- 同账号不同车、同数字 ID 不同来源实例、同时间不同充电记录、仅相近秒数及相同能量：均不得自动关联；一对多、多对一、来源字段缺失或冲突也不得折叠。
- 两条记录只有一条已同步到本地、分页未加载全、日期筛选边界不同、离线冷开或切换账号：不得隐藏唯一可见记录，也不得跨身份读取或让摘要重复计数。
- 两侧分别存在手工金额、只有一侧金额、金额相等或冲突、不同币种、真实零值和已删除标记：原手工数据均保留，冲突不可静默择一，原始 ID 和来源不得改写。
- 合格 archive 应显示真实 SOC 和电量；未验证 local_import 不得被冒充为整场观测；缺电价时保持未知而非造账单。映射撤销、重新同步和页面详情切换后，原记录仍可恢复、费用不丢失。
