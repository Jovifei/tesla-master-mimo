## 环境坑（本轮新踩）：workspace git 对象库被环境清空
- 症状：git checkout -b 后 HEAD "unknown revision"、"bad object HEAD"，refs/heads/main 指向的 commit 对象（11ba77d）从本地 objects 消失，git fetch 报 "unresolved deltas"，git gc 报 "refs/heads/main does not point to a valid object"。
- 根因：本环境会清空 submodule 的 objects（E:/project/tesla_master/.git/modules/app_mimo/objects）与分支 refs，且中途 git reset --hard 把工作区文件删掉了一大批（android/app/src 从数百文件掉到 51 个）。
- 恢复步骤（已打通，下次直接用）：
  1. 远端是唯一事实源（git ls-remote 权威），本地丢对象不影响远端。
  2. /tmp 新鲜 partial clone（--filter=blob:none）→ 拿到完整 pack（.git/objects/pack/*.pack+idx+rev+promisor）。
  3. 把 pack 拷回 workspace gitdir/objects/pack/，手写 HEAD（ref: refs/heads/main）与 refs/heads/main（写目标 SHA）。
  4. git rev-parse HEAD 能解析 → git checkout -f main 恢复工作区全部文件（38187 文件回来了）。
  5. 用 git show <commit>:<path> 把推送 commit 里的文件内容重落到工作区（因 checkout -f 会覆盖未提交改动）。
- 教训：本环境操作 git 不要用 checkout -b/reset --hard（会触发对象清空+工作区文件丢失）；优先用 /tmp 克隆 + cp pack 恢复。扁平 refs/heads 文件能存活，但 objects 会被清，所以关键改动第一时间 push 远端兜底。
