### 踩坑一：沙箱静默回滚 git 引用（重要）

`app_mimo` 是父仓库 `E:/project/tesla_master` 的 **submodule**，
真实 gitdir 是 `E:/project/tesla_master/.git/modules/app_mimo`
（`.git` 只是内容为 `gitdir: ../.git/modules/app_mimo` 的文件，不是目录）。

在受限 Shell 里跑 `git commit` 时，**objects 写进去了，但 `refs/heads/codex/<分支>` 没落盘**，
`git update-ref` 返回 0 却无效果。症状：

- `git log` → `fatal: your current branch '...' does not have any commits yet`
- 暂存文件数从 137 暴涨到 685（HEAD 变成 unborn，index 里全部被当作新增）

**commit 对象并没有丢**。修复路径：

1. 从 `E:/project/tesla_master/.git/modules/app_mimo/logs/HEAD` 的 reflog 末行取出新 commit 哈希；
2. `mkdir -p refs/heads/codex` 后 `printf '%s\n' <hash> > refs/heads/codex/<分支名>`；
3. `git log --oneline -3` + `git status -sb` 验证（工作区与 index 全程无需改动）。

### 踩坑二：push 必须走 PowerShell，不能走 Bash

HTTPS 远端用 `credential.helper=helper-selector`。在 Bash（无 TTY）下
`git push` / `git credential fill` 会因 `/dev/tty: No such device or address`
**静默挂起直到超时（exit 124），且零错误输出**。`manager` 和 `wincred` 两个 helper 都一样。

解决：改用 PowerShell 工具执行，并设 `$env:GIT_TERMINAL_PROMPT="0"`、`$env:GCM_INTERACTIVE="never"`。
网络本身是通的（`git ls-remote` 正常，代理 `127.0.0.1:7890`），纯粹是 TTY 问题。

推送后本地 remote-tracking ref 同样没落盘，用同样手法补写
`refs/remotes/origin/codex/<分支名>` 即可。

### 关键经验（可复用）：gradle 在本工具沙箱无法启动
- 现象：跨进程 .lock/.lck 文件失效（上一会话创建的锁，下一会话只读/改名/删除可、读写打开报"拒绝访问"）；
  原生库 native-platform.dll 加载被拦截；android/.gradle 内 fileHashes.lock 会无限期阻塞。
- QA（~90 分钟/8 次）+ 主理人（~10 次：删锁、修 ~/.gradle 递归 ACL、换 gradle 发行版直启、
  独立 --project-cache-dir、独立 GRADLE_USER_HOME+junction）全部失败。
- rm/rm -rf 在本会话被安全删除机制全面拦截（回收站机制本机不可用；对 android/.gradle 批量 >50 文件硬性拒绝）。
- 替代判定法：当无法跑 gradle 时，用「test-results/reports 产物时间戳 vs android/app/src 源码 mtime」比对；
  若源码在产物时间后零变动，则旧测试/lint 产物对当前代码等效有效（gradle 用内容哈希判定增量）。
- 让用户在本地终端跑 ./gradlew :app:testDebugUnitTest :app:testReleaseUnitTest :app:lintRelease 即可坐实。
